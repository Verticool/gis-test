# gis-test

SPA с интерактивной картой: три пользовательских слоя (температура, ветер, инсоляция), выбор времени и аналитика. Данные — мок-API, бэкенда нет. Область — район Бишкека, окно 10:00–14:00 с шагом 15 минут.

Демо: https://verti.cc/gis-test/ · Стек: React 19 · TypeScript · Vite 8 · Vedro 1.1 · OpenLayers 10 · Recharts 3 · Tailwind 4.

```
pnpm i
pnpm dev       # http://localhost:5173
pnpm build     # dist/
pnpm preview
pnpm lint      # tsc -b
```

В сборке стоит `base: '/gis-test/'` — приложение рассчитано на размещение по подпути: скопировать `dist/` в каталог статики.

## Как устроено

```
src/
  types/              контракты: LayerId, LayerFrame, LayerCell, LayerSeries
  config/             реестр слоёв, временная сетка
  lib/gis/            генерация мок-данных — чистые функции
  lib/api/            «бэкенд»: задержки, отмена, LRU-кэш кадров
  lib/map/            адаптер OpenLayers: подложка, кадры слоёв, рендер поля
  stores/             Vedro: состояние, селекторы, действия
  features/map/       React-обвязка карты, переключатель слоёв
  features/analytics/ сводка рядов и график на Recharts
  components/ui/      примитивы без бизнес-логики
  app/                провайдер стора и раскладка
```

Знания идут в одну сторону: `ui → features → stores → lib/* → types`. Карта и Recharts не знают друг о друге — их связывает только состояние. В `types/`, `config/` и `lib/` нет ни React, ни OpenLayers, ни Recharts.

- `types/` + `config/` — `LayerFrame` (кадр: сетка ячеек, границы значений, время) и `LayerDescriptor` (подпись, единицы, палитра, `renderKind`, прозрачность, диапазон, шаг сетки). Реестр слоёв — единственное место, где описан конкретный слой.
- `lib/gis/` — мок-данные не случайные: fBm-шум, градиент рельефа, остров тепла Бишкека гауссом, суточный ход, облачность, дрейф поля; у ветра на каждой ячейке своё направление.
- `lib/api/` — сеть: задержка 180–900 мс, `AbortSignal`, LRU-кэш кадров (24 записи, ключ `слой:время`). Здесь же точка подмены мока на реальный запрос.
- `lib/map/` — адаптер OL: на входе `LayerFrame` + `LayerDescriptor`, про Vedro и React не знает.
- `stores/` — состояние и use case'ы: загрузка, отмена, освобождение слоя, прогрев, снап времени.
- `features/*` — только представление: что показать и как нарисовать то, что лежит в сторе.

## Почему OpenLayers

- не нужен ключ: Mapbox и Google требуют токен — для тестового лишняя зависимость от внешнего сервиса;
- одна библиотека на оба типа отображения: растр (`ImageStatic` — поле, отрисованное в canvas) и вектор (стрелки, полигоны);
- прямой контроль видимости и порядка слоёв — на нём держится инвариант «виден один слой»;
- React-обвязка не обязательна: инстанс карты живёт в одном `useEffect`, обёртки вроде react-map-gl навязывают свои компоненты.

Подложка — Esri World Gray Canvas: тайлы без ключа, светлая, данные на ней читаются. CARTO Positron отпал не по статусу (тайл отдавался с 200), а по картинке: вместо карты приходила заглушка «API KEY REQUIRED».

Цена выбора: готового 3D нет (доп. задание не сделано), стилизация вектора беднее, чем Mapbox Style Spec.

## Состояние в Vedro

| поле | что это |
| --- | --- |
| `activeLayerId` | активный слой; в UI он всегда один, поэтому не nullable |
| `selectedTime` | выбранная точка времени, unix ms |
| `frameById` | по слою: `status` (`idle/loading/ready/error`), `requestId`, `requestedTime`, `data`, `error` |
| `seriesById` | временные ряды для графиков |

Ключ по слою, а не одно поле «текущие данные»: состояние слоёв не затирает друг друга, а по `requestId` видно, чей ответ пришёл.

Почему не `useState`: Vedro перерисовывает только компонент, чей срез изменился. Селекторы читают переключатель слоёв и панель графика, а карта подписана императивно (`store.on('frameById', …)`) — смена времени не ререндерит React. Селекторы — модульные функции, а не фабрики: библиотека сравнивает результат по значению, поэтому тяжёлые кадры в них не попадают — их читает адаптер карты через `store.get`. Вся асинхронность на Vedro; `react-query` не подключён сознательно, иначе у одного async-состояния было бы два владельца.

## Как связаны время, данные, карта и графики

```
клик по графику / кнопка слоя
        │  action: setSelectedTime / selectLayer
        ▼
Vedro: selectedTime, activeLayerId, статусы
        │  useDataSync: ensureFrame / ensureSeries
        ▼
lib/api: задержка, AbortController, LRU-кэш
        │  dispatch(data)
        ▼
┌───────┴────────┐
▼                ▼
карта            график
store.on(…)      useSelector(…)
→ lib/map.render → chartRows → Recharts
```

Timeline здесь — сам график: он показывает ряд и позволяет выбрать точку времени кликом или тапом (`PlotTimePicker` + `ReferenceLine`). Отдельного слайдера нет намеренно: два контрола времени пришлось бы синхронизировать между собой, а график уже связан и со стором, и с картой. Связь двусторонняя: данные идут в карту и график, клик по графику меняет состояние карты.

## Гонки и асинхронность

- На каждый слой свой `AbortController`: новая загрузка отменяет предыдущую, отмена не считается ошибкой.
- У каждого ответа `requestId`; ответ с устаревшим номером в стор не попадает.
- Переключение слоя освобождает предыдущий: запрос отменяется, кадр и статус уходят из стора, геометрия снимается с карты.
- Время снапится к сетке (`nearestTimePoint`): кэш и статусы должны ключеваться по стабильному значению.
- Инвариант карты — виден максимум один слой данных. Пока картинка растра декодируется, видимого слоя нет вовсе; поздно догрузившаяся картинка не показывается, если активный слой успел смениться. Проверено фаззингом: 300 прогонов со случайным порядком слоёв и догрузки картинок — двух видимых слоёв не возникает.
- Ошибка попадает в стор как `error`, на кнопке слоя появляется повтор (`retryLayer`).

## Производительность

- Кадры кэшируются (LRU 24) и прогреваются через 500 мс после смены времени: ряды всех слоёв, кадры остальных слоёв, соседние точки активного. Переключение по прогретому кэшу — 60–85 мс, холодная точка — около 400 мс.
- Растр не держит тысячи объектов: поле рисуется в canvas (18 px на ячейку) и отдаётся карте одной картинкой; вектор пересобирается только при смене кадра.
- Смена времени не ререндерит React, Recharts получает уже сведённые строки (`chartRows`), а не сырые ряды.
- Бандл 880 КБ (≈261 КБ gzip), почти всё — OpenLayers. Следующий шаг — ленивый `import()` карты.

## Масштабирование на 100+ слоёв

Добавить слой = добавить запись в `LAYER_REGISTRY` и билдер данных: UI и стор читают реестр, хардкода по конкретным слоям нет. Состояние разложено по ключу слоя, поэтому статусы и кадры не конфликтуют. Что придётся переделать: виртуализовать список слоёв; вместо одного активного хранить множество видимых (`Set<LayerId>`) с z-порядком; грузить кадры тайлами и по уровню детализации; генерацию и canvas-рендер унести в воркер; кэш сделать оконным по времени; селекторы разнести по слоям, чтобы подписки не были широкими; аналитику строить по набору выбранных слоёв.

## Сознательные компромиссы

- Один активный слой вместо накладывающихся — проще состояние и проверки, при этом модель под несколько слоёв уже готова.
- Время выбирается графиком, отдельного timeline-компонента нет.
- Цвет растра нормализуется по текущему кадру, а не по паспортному диапазону: иначе большая часть области выглядит плоской. Цена — цвета нельзя сравнивать между кадрами.
- Данные синтетические; «загрузка» — задержка в мок-API.
- 3D-объект из дополнительного задания не делал.
- Область данных фиксирована, независимо от зума.

## AI-инструменты

Связка: **Hermes Agent** как оркестратор (планирование, правки по файлам, прогон проверок) на **DeepSeek Flash**; рутинные правки и прогоны уходили на локальный воркер — **KAT-Coder/Qwen-Code на llama.cpp**, без внешних лимитов.

Как делилась работа:

- **Моё:** постановка и границы задачи (стек, что входит и что нет), архитектура и её границы (`lib/map/` не знает про Vedro, `stores/` — про OpenLayers, UI отделён от состояния), состав состояния и форма ключей, стратегия гонок (`AbortController` + `requestId`), инвариант «виден один слой», правила кэша и прогрева, продуктовые решения (один активный слой вместо стека, время через график, без слайдера), визуальный тон, прозрачности и мобильная раскладка.
- **Ассистента:** набор кода и стилей под этими указаниями — обвязка OpenLayers, генератор мок-поля, свёртка рядов для Recharts, вёрстка, проверочные харнессы.

Каждую итерацию возвращал на доработку — по конкретным замечаниям: моки выглядели неправдоподобно (переписали модель поля, а не подкрутили значения), переключение слоёв тормозило на секунду (появились кэш кадров и прогрев), при быстром переключении на карте оказывались два слоя сразу (появился инвариант и фаззинг-тест на него), заливки перекрывали подложку (прозрачности пересчитаны), лишний блок статуса и «машинные» заголовки убраны. Финальный вид вычитывал вручную — вплоть до отступов.

Что предлагалось и было отклонено: `@tanstack/react-query` и `react-error-boundary` (второй владелец async-состояния), папки по доменам (лишняя изоляция для размера задачи), тайлы CARTO Positron (заглушка «API KEY REQUIRED» при статусе 200), нормализация растра по общему диапазону (заменена на по-кадровую), отдельный слайдер времени и боковая колонка слоёв, высокая непрозрачность заливок.

Ничего не принималось на веру: поведение проверялось харнессами (гонки — фаззингом на 300 прогонов) и замерами в браузере, оттуда вылезли гонка растра и неработающий `ReferenceArea`. Тем же инструментом разбирал причины уже написанного кода — почему клик по графику не менял время (путь заливки лежал выше перехватчика в DOM) и откуда бралась чёрная рамка вокруг графика (браузерный focus-outline на SVG, который Recharts делает фокусируемым).
